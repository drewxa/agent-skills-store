# Правила приватности

Публикуйте только то, что можно без ограничений показать постороннему человеку. Это относится к текущим файлам, истории Git, примерам, изображениям, логам, issues и pull request.

## Что нельзя добавлять

- Пароли, API-токены, токены ботов, приватные SSH-ключи, сертификаты с закрытым ключом, cookies, сессии и коды восстановления.
- Реальные chat ID, телефоны, личные email, адреса, платёжные реквизиты и другие личные идентификаторы.
- Частные переписки, историю запросов, личную память агента, внутренние документы и клиентские данные.
- Приватные ссылки, ссылки с авторизацией в параметрах, внутренние адреса серверов и содержимое локальных конфигураций.
- Скриншоты, записи, базы данных, архивы и логи без проверки содержимого и метаданных.
- Привязанные к владельцу абсолютные пути и названия внутренних проектов, если они раскрывают частный контекст.
- Чужие материалы без права на публикацию.

## Как описывать настройку

Скилл объясняет, какие параметры ему нужны, где пользователь задаёт их локально и что произойдёт при их отсутствии. Он не содержит действующих доступов и адресатов.

Например, для интеграции с Telegram можно описать переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Их значения задаются на каждом ноутбуке вне репозитория. Этот пример не реализует отправку сообщений.

Для документации используйте явные заглушки вида `<YOUR_TOKEN>` и вымышленные данные. Пример файла настроек содержит только имена параметров и безопасные заглушки. Не копируйте реальные значения с последующим частичным маскированием.

В скриптах не печатайте секреты, содержимое окружения целиком или URL запросов с токенами. Сообщения об ошибках также должны быть безопасны для публикации.

## Проверка перед публикацией

- Прочитайте весь diff, включая вспомогательные файлы, а не только `SKILL.md`.
- Проверьте новые файлы и скрытые папки: они могут не попасть в обычный diff до добавления в индекс.
- Проверьте метаданные коммита: имя и email автора тоже становятся публичными. Используйте выбранную вами публичную Git-идентичность, например GitHub noreply.
- По возможности запускайте сканер секретов. Автоматическая проверка не распознаёт все личные данные и не заменяет чтение.
- После push проверьте опубликованный список файлов.

Если сомневаетесь, оставьте сомнительный материал вне репозитория и замените его общим описанием. Если секрет уже попал в Git, следуйте [порядку действий](SECURITY.md).
