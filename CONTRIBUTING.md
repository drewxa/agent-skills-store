# Как добавлять и менять скиллы

## Новый скилл

1. Уточните его назначение: какую задачу решает, когда применяется и какой результат даёт.
2. Создайте папку `skills/<skill-name>/` и файл `SKILL.md` в формате, который поддерживает целевой агент. Для совместимых с Agent Skills агентов укажите YAML-поля `name` и `description`.
3. Опишите необходимые настройки, зависимости, ограничения и поведение при ошибках. Параметры конкретного пользователя вынесите за пределы репозитория.
4. Добавляйте скрипты и справочные материалы только по необходимости. Не включайте временные результаты работы агента.
5. Проверьте применение скилла на вымышленных данных. Для действий с внешними последствиями используйте безопасный тестовый сценарий.
6. Добавьте ссылку на скилл в `skills/README.md`.

Не создавайте пустые скиллы под будущие идеи: добавляйте папку, когда начата работа над её содержимым.

## Изменения с нескольких ноутбуков

Перед работой выполните `git pull --ff-only`. Делайте небольшие коммиты и отправляйте их после проверки. На другом ноутбуке сначала получите эти изменения.

Если Git сообщает о расхождении истории, разберите различия и сохраните нужные изменения с обеих сторон. Не используйте принудительный push как обычный способ синхронизации.

## Перед коммитом

Прочитайте [PRIVACY.md](PRIVACY.md), проверьте `git status --short` и `git diff`. Добавьте нужные файлы явно, затем прочитайте `git diff --cached` целиком. Убедитесь, что примеры вымышленные, настройки переносимы и права на материалы позволяют публикацию.

В сообщении коммита опишите результат изменения без личного контекста. При заметном изменении поведения опишите его в pull request и укажите, как проверяли.
