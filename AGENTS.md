# Правила работы с репозиторием

Это публичный репозиторий универсальных скиллов. Применяй эти правила ко всем изменениям, включая документацию, примеры, скрипты, комментарии, сообщения коммитов и описания pull request.

## Границы задачи

- Добавляй или меняй только скиллы, которые попросил пользователь. Перечень идей не является поручением реализовать их.
- Каждый скилл хранится в `skills/<skill-name>/SKILL.md`; вспомогательные файлы — внутри той же папки.
- Не копируй локально установленные скиллы без отдельного поручения. Сначала проверь приватность и права на их публикацию.
- Не меняй глобальные инструкции агента и не перезаписывай установленные скиллы при подготовке репозитория.

## Приватность

- Перед записью и публикацией прочитай `PRIVACY.md`.
- Не переноси в репозиторий личную память пользователя, историю бесед, реальные переписки, рабочие документы и настройки его устройств.
- Не записывай токены, ключи, пароли, cookies, идентификаторы личных чатов и приватные ссылки. Не выводи секреты в журнал проверки.
- Используй вымышленные примеры и переносимые пути. Настройки пользователя передавай через переменные окружения или внешние локальные файлы.
- Не добавляй инструкции автоматически загружать `.env`, ключи или конфигурацию с доступами из публичных источников.
- `.gitignore` — вспомогательная защита, а не подтверждение безопасности. Он не скрывает уже отслеживаемые файлы.

## Перед коммитом и push

1. Проверь `git status --short` и список добавляемых файлов, включая новые и скрытые файлы.
2. Добавляй файлы явно по именам; просмотри полный `git diff --cached`.
3. Проверь текст, примеры, вложения и метаданные на секреты и личные данные. Для бинарных файлов нужна отдельная проверка содержимого и метаданных.
4. Если скилл содержит скрипты, проверь заявленный сценарий и обработку отсутствующих настроек. Не отправляй реальные сообщения и не вызывай платные действия только ради теста без разрешения.
5. Проверь переносимость: нет обязательного имени пользователя, личного пути или доступа, работающего только на одном ноутбуке.
6. Публикуй только проверенные файлы. Если обнаружена утечка, действуй по `SECURITY.md`.

Скилл сам по себе не даёт разрешения отправлять сообщения, публиковать данные или выполнять другие внешние действия: учитывай текущий запрос пользователя и правила среды.
