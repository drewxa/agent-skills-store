# Использование на нескольких ноутбуках

На каждом ноутбуке хранится отдельный клон одного репозитория. GitHub служит общей точкой обмена изменениями.

## Первый запуск

1. Установите Git, если он ещё не установлен.
2. На странице GitHub нажмите **Code** и скопируйте URL клонирования.
3. В выбранной рабочей папке выполните `git clone <REPOSITORY_URL>` и перейдите в созданный каталог.
4. Для отправки изменений настройте свой доступ GitHub на этом ноутбуке. Приватные ключи и токены не кладите в клон.
5. Настройте публичное имя и email для коммитов. Сначала проверьте `git config user.name` и `git config user.email`; затем задайте желаемые значения через `git config --local user.name "<PUBLIC_NAME>"` и `git config --local user.email "<PUBLIC_EMAIL>"`. Реальный email не обязателен: можно использовать адрес noreply из настроек GitHub.

## Подключение к агенту

Клонирование само по себе не устанавливает скиллы. Найдите в документации вашего агента поддерживаемую папку скиллов и способ установки.

Можно копировать выбранные папки из `skills/` в каталог скиллов агента. После `git pull` копии нужно обновлять отдельно. Перед заменой сравните их с установленными версиями, чтобы сохранить локальные изменения.

Если агент поддерживает ссылки на папки, можно подключить отдельные скиллы ссылками на их папки в клоне. Тогда обновление клона обновит их содержимое. Поддержку ссылок и команды их создания проверяйте для своей ОС и агента; не заменяйте существующую папку без сравнения.

Секреты и локальные параметры задавайте вне клона, отдельно на каждом ноутбуке. Не переносите их через Git. Не импортируйте содержимое своего каталога скиллов целиком: в нём могут быть приватные настройки и чужие материалы.

## Обычный цикл

Перед редактированием:

```sh
git status --short
git pull --ff-only
```

Если есть незавершённые изменения, сначала сохраните их и разберите различия. Затем отредактируйте нужный скилл и проверьте результат:

```sh
git diff
git add <CHANGED_FILE>
git diff --cached
git commit -m "Describe the skill change"
git push
```

Повторите `git add` для каждого проверенного файла. На втором ноутбуке выполните `git pull --ff-only`, затем обновите установленные копии скиллов, если используете копирование.

Получайте изменения перед работой и отправляйте после неё. Git не синхронизирует незакоммиченные файлы, а личные настройки остаются локальными.
